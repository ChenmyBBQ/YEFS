# YEFS 架构文档

## 1. 文档说明

本文档面向产品、项目管理和协同开发成员，用于说明 YEFS 项目的整体技术架构、运行链路、模块职责和集成方式。本文档重点回答以下问题：

- 项目如何启动、运行和退出。
- 主工程、QML、插件和第三方库分别承担什么职责。
- 地图、设置、消息、插件等核心能力如何协同工作。
- 当前项目的主要扩展点和构建部署方式是什么。

本文档不展开第三方库内部实现细节，也不作为 API 参考手册使用。

## 2. 项目概览

YEFS 是一个基于 Qt 6、QML、MapLibre 和 HuskarUI 构建的 GIS 地面站项目。整体结构可概括为四层：

- 应用生命周期层：负责应用初始化、QML 引擎创建、核心单例注册、插件加载与退出清理。
- 核心服务层：负责消息通信、配置管理、地图引擎桥接、地图解析、单位和坐标转换等通用能力。
- 界面与交互层：使用 QML 构建主窗口、菜单、地图页面、设置页面和业务交互入口。
- 插件扩展层：通过统一插件接口接入独立业务模块，目前代表性插件为空域管理插件。

## 3. 启动与生命周期

### 3.1 启动入口

启动入口位于 `src/cpp/main.cpp`。

启动阶段的主要动作如下：

1. 创建 `QGuiApplication`。
2. 配置日志输出到 `yefs_debug.log`，便于定位启动和退出过程问题。
3. 创建 `YEFS::Application` 实例。
4. 调用 `initialize()` 完成框架初始化。
5. 注册自定义主题。
6. 调用 `run()` 加载主界面并进入 Qt 事件循环。

### 3.2 初始化流程

初始化主流程位于 `src/core/Application.cpp` 的 `Application::initialize()`，关键步骤如下：

1. 设置渲染和应用基础参数。
   - 设置 `QSG_RENDER_LOOP=basic`。
   - 设置应用组织名、应用名、版本号。
   - 配置 MapLibre 对应的图形后端。

2. 创建 `QQmlApplicationEngine`。

3. 初始化 HuskarUI。
   - 调用 `HusApp::initialize(m_engine)`，为 QML 界面提供 HuskarUI 组件支持。

4. 注册 QML 类型和单例。
   - 包括 `MessageBus`、`MapLibreEngine`、`SettingsManager`、`UnitManager`、`CoordinateConverter`、`PluginManager` 等。
   - `DBCompt` 作为动态库组件，以 QML 单例方式手动注册。

5. 初始化数据库组件。
   - 读取 `AppConfig/db_schema.json`。

6. 加载所有插件。
   - 调用 `PluginManager::loadAllPlugins()`。

7. 初始化地图解析体系。
   - 注册 GeoJSON、GPX、KML 解析器。
   - 初始化 `MapSourceManager` 与 `OnlineMapProviderManager`。

8. 连接应用退出清理逻辑。

### 3.3 运行阶段

`Application::run()` 负责加载主 QML：

- 主入口页面为 `qrc:/YEFSApp/qml/Main.qml`。
- QML 加载成功后，应用进入事件循环。
- 系统会通过 `MessageBus` 发布 `app/ready` 主题，供界面或模块感知应用已就绪。

### 3.4 退出与清理

清理逻辑由 `Application::cleanup()` 执行，遵循依赖逆序释放原则：

1. 销毁 `PluginManager`，触发插件 `shutdown()`。
2. 销毁 QML 引擎，释放地图与界面资源。
3. 依次销毁 `UnitManager`、`MapSourceManager`、`OnlineMapProviderManager`、`MapParserFactory`、`MapLibreEngine`、`AppIconManager`、`NerdIcon`、`DBCompt`、`SettingsManager`、`MessageBus`。

这种顺序可以降低地图线程、数据库连接和消息回调残留的风险。

## 4. 目录结构与职责

### 4.1 顶层目录说明

- `src/`：主工程源码，包含 C++ 核心、QML 页面、资源和数据库组件接入。
- `plugins/`：业务插件目录，目前已接入空域管理插件。
- `3rdparty/`：第三方依赖源码，主要包括 HuskarUI 和 maplibre-native-qt。
- `docs/`：项目说明与专题文档。
- `AppConfig/`：运行时配置和数据库模式文件。
- `out/`：构建产物输出目录。
- `build/`：CMake 构建目录。

### 4.2 主工程源码结构

- `src/core/`：核心服务与框架能力。
- `src/cpp/`：程序入口和部分历史兼容代码。
- `src/qml/`：QML 界面入口、页面与全局菜单定义。
- `src/resources/`：图标、字体、着色器等资源。
- `src/dbcompt/`：数据库组件接入层。

## 5. 核心模块架构

### 5.1 Application

`YEFS::Application` 是全局协调者，职责包括：

- 管理应用初始化与退出。
- 创建 QML 引擎。
- 注册 QML 类型和单例。
- 初始化数据库、插件和地图解析器。
- 加载主界面并进入事件循环。

### 5.2 MessageBus

`MessageBus` 是运行时消息通信中心，用于在 C++、QML 和插件之间进行解耦通信。

适用场景包括：

- 地图点击、地图状态变化广播。
- 空域绘制状态同步。
- 页面之间的轻量事件通知。
- 启动阶段的视觉状态收口。

MessageBus 让页面之间不必直接持有对方引用，是当前项目最重要的运行时胶水层之一。

### 5.3 SettingsManager

`SettingsManager` 负责全局配置读取和保存。它对上提供统一的 QML 调用接口，对下承担持久化职责。

当前主要用于：

- 地图样式和默认缩放级别。
- 应用设置项统一读写。
- 单位制与其他偏好配置的保存。

### 5.4 PluginManager

`PluginManager` 是插件系统的入口，职责包括：

- 维护插件搜索路径。
- 扫描插件目录。
- 加载和卸载插件。
- 提供插件实例和插件 QML 入口查询。

QML 可通过 `PluginManager.getPlugin()`、`getPluginQmlEntry()`、`getPluginSettingsPage()` 等接口访问插件暴露的能力。

### 5.5 MapLibreEngine

`MapLibreEngine` 是地图内核桥接层，负责把 MapLibre Native Qt 以统一接口暴露给 QML 和插件。

核心职责包括：

- 相机控制：中心点、缩放、俯仰、朝向、飞行动画。
- 地图样式切换。
- GeoJSON 图层增删改查。
- 地图点击事件上报到消息总线。
- 维护当前相机状态和图层状态。

它在架构中的定位是“地图能力服务”，上游被 QML 页面调用，下游对接 MapLibre Native Qt。

### 5.6 地图解析与数据源管理

地图解析与数据源体系由以下部分组成：

- `IMapParser`：解析器接口。
- `MapParserFactory`：解析器工厂。
- `MapSourceManager`：地图源管理器。
- `OnlineMapProviderManager`：在线地图提供商管理器。

当前主工程已经注册 GeoJSON、GPX、KML 三类解析器，并具备在线地图提供商管理框架。

### 5.7 UnitManager 与 CoordinateConverter

这两个模块属于通用支撑服务：

- `UnitManager`：负责高度、距离、速度、温度、压力等单位换算和格式化。
- `CoordinateConverter`：负责经纬度、UTM、MGRS 等格式转换与显示。

这类能力是地图页面、任务规划和航空场景显示的基础支撑模块。

## 6. QML 界面架构

### 6.1 主窗口骨架

主界面入口为 `src/qml/Main.qml`，主要结构包括：

- `HusWindow`：作为应用主窗口。
- 左侧菜单：使用 `HusMenu` 承载功能导航。
- 主内容区：使用 `Loader` 动态加载页面。
- 设置页加载器：与主内容页并行存在，通过显示状态切换。
- 启动遮罩：用于收敛地图初始化过程中的视觉过渡问题。

### 6.2 菜单与导航定义

菜单结构定义在 `src/qml/YefsGlobal.qml`，其职责是：

- 统一维护菜单分组和子菜单项。
- 定义菜单的标签、图标、状态和跳转页面。
- 构建搜索用的选项集合。

当前菜单结构覆盖：

- 地图
- 航线规划
- 空域管理
- 数据管理
- 地图工具

### 6.3 页面组织方式

`src/qml/Home/` 用于承载主业务页面，例如：

- `MapPage.qml`：地图主页面，是当前多个功能入口的实际落点页面。
- `SettingsPage.qml`：系统设置页面。

当前界面层以“单地图主页面 + 多入口汇聚”为主要组织方式，说明系统仍处于由统一地图页承接多业务能力的阶段。

## 7. 插件机制

### 7.1 插件接口

所有插件都必须实现 `IPlugin` 接口，核心契约包括：

- 生命周期：`initialize()`、`shutdown()`。
- 元信息：`id()`、`name()`、`version()`、`pluginType()`。
- UI 扩展点：`qmlEntry()`、`settingsPage()`、`toolbarItem()`、`sidePanel()`。

### 7.2 插件上下文

插件通过 `PluginContext` 访问宿主服务。上下文提供以下能力：

- 获取宿主服务对象。
- 通过消息总线发送消息。
- 读取和写入插件配置。

这使插件可以复用主工程中的消息、地图、配置等基础设施，而不直接耦合应用内部实现。

### 7.3 空域管理插件

当前最完整的业务插件是 `plugins/AirspaceManagerPlugin/`。

该插件在初始化阶段完成：

1. 数据库初始化。
2. 空域数据模型加载。
3. 图形生成器创建。
4. 绘制控制器创建。
5. 连接宿主消息总线。
6. 将已保存空域重新加载到地图。

插件内部的重要对象包括：

- `AirspaceDatabase`：持久化层。
- `AirspaceModel`：空域数据模型。
- `ShapeGenerator`：几何图形生成器。
- `DrawingController`：绘制交互状态机。

`DrawingController` 通过 `map/clicked`、`map/hovered`、`airspace-manager/draw`、`airspace-manager/finish`、`airspace-manager/cancel` 等主题驱动绘制流程，是目前插件化业务中最完整的一条交互闭环。

## 8. 地图与第三方依赖集成

### 8.1 HuskarUI

HuskarUI 是当前 QML 界面的主要组件库。主工程通过 `import HuskarUI.Basic` 使用其窗口、按钮、菜单、提示、输入和布局等组件。

项目在构建后会将 HuskarUI 的 QML 模块、插件和 DLL 一并复制到运行目录，以保证运行时可正确导入。

### 8.2 MapLibre Native Qt

MapLibre 提供地图渲染能力，主工程通过 `MapLibreEngine` 和 QML `MapLibre` 组件实现地图展示与交互。

构建层面启用了以下能力：

- Quick 插件
- Location 支持
- OpenGL 渲染

运行时会把 MapLibre 的 QML 模块和 GeoServices 插件复制到输出目录。

### 8.3 资源系统

项目使用 Qt Resource System 管理资源，主要包括：

- 应用图标
- 空域形状图标
- 字体文件
- 着色器资源
- QML 文件

主 QML 模块 `YEFSApp` 通过 `qt_add_qml_module` 进行打包和注册。

## 9. 构建与部署链路

### 9.1 构建组织

顶层 `CMakeLists.txt` 负责：

- 定义输出目录：`out/<BuildType>/bin` 与 `out/<BuildType>/lib`。
- 构建第三方依赖 HuskarUI 和 MapLibre。
- 再构建主工程 `src/`。
- 最后构建插件 `plugins/AirspaceManagerPlugin`。

### 9.2 主工程构建

`src/CMakeLists.txt` 负责：

- 创建可执行文件。
- 声明 `YEFSApp` QML 模块。
- 注册核心 C++ 源文件到 QML 模块。
- 打包图标、字体、着色器等资源。
- 链接 Qt、DBCompt、HuskarUI、MapLibre。

### 9.3 运行时复制

构建完成后，系统会自动复制以下内容到输出目录：

- HuskarUI 基础模块与实现模块。
- HuskarUI 对应插件和 DLL。
- MapLibre QML 模块。
- MapLibre Location 模块。
- MapLibre GeoServices 插件。

这套机制确保最终可执行文件所在目录具备完整运行依赖。

## 10. 当前架构特点与边界

### 10.1 架构特点

- 主体结构清晰，核心服务与界面逻辑已分层。
- 插件机制已经落地，具备继续扩展业务模块的基础。
- 地图与通用支撑能力已具备独立服务化形态。
- 空域插件形成了相对完整的“页面交互 + 消息通信 + 图形生成 + 数据落库”闭环。

### 10.2 当前边界

- 多个业务菜单仍共用 `MapPage.qml`，说明独立业务页面拆分尚未完成。
- 地图解析与在线地图管理具备框架，但并非所有菜单项都已有完整业务闭环。
- 产品层能力广度已经铺开，但成熟度仍以地图主页面和空域插件为主。

## 11. 结论

YEFS 当前已经形成以 Qt/QML 为界面基础、以 MapLibre 为地图引擎、以 MessageBus 为解耦手段、以 PluginManager 为扩展入口的整体架构。主工程提供稳定的生命周期、配置、地图和解析支撑，空域管理插件则验证了插件化业务落地路径。

从项目阶段判断，YEFS 已经具备继续扩展航线规划、地图工具、数据管理等业务模块的良好架构基础，但在功能完备度上仍处于“核心底座已成型、业务模块持续填充”的阶段。
